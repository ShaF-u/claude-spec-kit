# speckit-constitution 要件チェックリスト

## スコープ
- [ ] 作業は `.specify/memory/constitution.md` の更新のみ。テンプレートやコマンドは変更しない
- [ ] 入力を「憲章の内容」と「それ以外の意図（実装・生成・リファクタ・ビルド・デプロイ）」に分類し、後者は実行せず deferred として記録
- [ ] アプリのソース・テスト・デプロイ設定等を作成/変更/削除しない
- [ ] 憲章の内容か不明なら変更前に確認
- [ ] deferred があれば最後に `Next Actions` を出し、元の意図と適切な後続コマンド（/speckit-specify 等）を提案（呼び出さない）。無ければ省略

## 手順
- [ ] `resolve-template.ps1 constitution-template -Json` を実行し TEMPLATE_CONTENT を得る。失敗したら停止して報告（1レイヤーだけで続けない）
- [ ] 既存の constitution.md があれば現在値・修正履歴の情報源として読み、まだ有効な情報は保持。無ければテンプレートを初期文書に
- [ ] テンプレートのレイヤーには書き戻さない
- [ ] `[ALL_CAPS]` プレースホルダを全て特定。原則の数はユーザー指定があればそれに従う

## 値の決定
- [ ] ユーザー入力 → 無ければリポジトリ（README、docs、既存憲章）から推測
- [ ] RATIFICATION_DATE は当初採択日（不明なら聞くか TODO）、LAST_AMENDED_DATE は変更があれば今日
- [ ] CONSTITUTION_VERSION は semver: MAJOR=原則の削除/再定義、MINOR=原則/セクション追加や実質的拡充、PATCH=文言・誤字。曖昧なら理由を示してから確定

## 執筆
- [ ] テンプレート構造でプレースホルダを全て具体化（意図的に残す場合は理由を明記）
- [ ] 見出し階層を保持。置換後のコメントは有用でなければ削除
- [ ] 各原則: 名前行、非交渉のルール、（自明でなければ）根拠
- [ ] Governance: 改定手続き、バージョン方針、遵守レビュー
- [ ] 先頭に HTML コメントで Sync Impact Report（旧→新バージョン、変更した原則、追加/削除セクション、保留 TODO）。コミット前に人が削除する一時物

## 検証と出力
- [ ] 未説明のブラケットが残らない、バージョン行とレポート一致、日付は YYYY-MM-DD、原則は宣言的・検証可能・曖昧語なし（should → MUST/SHOULD と根拠）
- [ ] 見出しはテンプレート通り、セクション間は空行1つ、末尾空白なし
- [ ] `.specify/memory/constitution.md` に上書き保存（これ以外は書かない）
- [ ] 部分更新でも検証とバージョン判断は行う。重要情報が不明なら `TODO(<FIELD>): 説明` を入れレポートの保留に含める
- [ ] 報告: 新バージョンと理由、TODO/保留、コミットメッセージ案、Next Actions（あれば）。日本語
